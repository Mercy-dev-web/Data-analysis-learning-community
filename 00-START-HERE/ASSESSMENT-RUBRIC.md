# Assessment Rubric

This rubric explains how assignments and projects should be reviewed. It rewards sound thinking, accuracy, reproducibility and communication—not just attractive formatting.

## Scoring framework

| Criterion | Weight | What good work demonstrates |
|---|---:|---|
| Understanding the problem | 15% | Clearly states the question, audience and objective |
| Data understanding and quality | 15% | Understands fields, checks quality and documents limitations |
| Method and technical execution | 25% | Uses appropriate formulas, queries, transformations or code correctly |
| Accuracy and validation | 20% | Checks calculations, row counts, joins and key results |
| Interpretation and recommendations | 15% | Explains evidence accurately and makes relevant recommendations |
| Presentation and documentation | 10% | Organised, readable, reproducible and clearly explained |
| **Total** | **100%** | |

## Performance levels

### 90–100: Excellent
Work is accurate, thoughtful and independently explained. Methods are appropriate, validation is clear, and insights are well supported. Documentation makes the work easy to reproduce.

### 80–89: Very good
Work meets the objectives with only minor errors or gaps. The learner explains most decisions and communicates findings clearly.

### 70–79: Pass
The main task is completed and the core concepts are understood. Some explanations, checks or presentation details may need improvement, but the analysis is broadly sound.

### 60–69: Revision required
There is evidence of learning, but important gaps remain. The learner should correct the identified issues and resubmit.

### Below 60: Further practice required
The work does not yet demonstrate the required understanding. Revisit the lesson and complete the foundational exercises before resubmitting.

## Critical errors

Regardless of visual quality, the following issues should trigger revision:
- Incorrect calculations that materially change the conclusion.
- A join that duplicates records or inflates totals without being noticed.
- Removing records or values without documenting the decision.
- Presenting correlation as proof of causation.
- Making recommendations that are not supported by the analysis.
- Publishing private or confidential information.
- Submitting work the learner cannot explain.

## Tool-specific checks

### Excel
- Formulas reference the intended cells and ranges.
- Criteria in conditional functions are correct.
- Missing values and duplicates are handled deliberately.
- PivotTable totals reconcile with the source.
- Charts have clear labels and do not distort the message.

### SQL
- Queries return the intended rows and columns.
- Filters and NULL handling are appropriate.
- GROUP BY and aggregate logic are correct.
- Joins use appropriate keys and do not unexpectedly multiply records.
- Queries are readable and results are interpreted accurately.

### Power BI
- Data types and transformations are correct.
- Relationships reflect the data's grain.
- Measures produce expected results and are validated.
- Visuals answer specific questions.
- Filters and interactions behave as intended.

### Python
- Notebook runs from top to bottom.
- Code is readable and uses appropriate data types.
- Cleaning decisions are explained.
- Results are reproducible.
- Visualisations have meaningful labels and interpretations.

## Milestone progression

| Milestone | Evidence required | Pass standard |
|---|---|---:|
| Week 2 | Data-quality audit and problem brief | 70% |
| Week 5 | Excel project and written interpretation | 70% |
| Week 8 | SQL project using related tables | 70% |
| Week 11 | Power BI report and model explanation | 70% |
| Week 14 | Reproducible Python EDA notebook | 70% |
| Week 16 | Capstone, portfolio README and presentation | 70% |

A learner who does not meet the threshold should receive specific feedback, revise the work and resubmit. The goal is demonstrated understanding, not simply moving through the calendar.

## Feedback template

Use this structure when reviewing an assignment:

**What was done well**
- Identify specific strengths and correct decisions.

**What needs improvement**
- Identify the exact error, omission or unclear explanation.

**Why it matters**
- Explain how the issue affects accuracy, interpretation or usability.

**Required correction**
- State what the learner should change or demonstrate.

**Review outcome**
- Pass / Revision required.

## Reviewer principles

- Be specific, respectful and consistent.
- Evaluate the work against the task and the learner's current stage.
- Do not reward decorative dashboards over accurate analysis.
- Distinguish a small formatting issue from an error that changes the result.
- Ask learners to explain their reasoning when authorship or understanding is unclear.

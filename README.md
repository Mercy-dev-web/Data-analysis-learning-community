# Data Analysis Learning Community

A practical, beginner-friendly, 16-week learning programme for people who want to learn how to work with data, answer business questions, and communicate useful findings.

**The goal is not just to learn tools. The goal is to become someone who can take a question, work with data, find evidence, and explain what should happen next.**

## Start here

1. Read the [Programme Roadmap](00-START-HERE/PROGRAMME-ROADMAP.md) before beginning.
2. Read the [Learner Handbook](00-START-HERE/LEARNER-HANDBOOK.md). It explains the rules, weekly routine, submission expectations and progression requirements.
3. Use the [Assessment Rubric](00-START-HERE/ASSESSMENT-RUBRIC.md) to understand how your work will be evaluated.
4. Track your progress with the [Weekly Progress Tracker](00-START-HERE/WEEKLY-PROGRESS-TRACKER.md).

## Who this programme is for

- Complete beginners with little or no data analysis experience.
- Students, graduates, career changers and working professionals.
- Learners willing to practise consistently and explain their reasoning.
- People interested in business, marketing, finance, operations, public service and other fields where data can support decisions.

No previous programming experience is required. You should have access to a computer. A spreadsheet application is needed for the Excel section; later sections introduce SQL, Power BI and Python.

## Programme at a glance

| Weeks | Learning area | Main outcome |
|---|---|---|
| 1–2 | Data analysis foundations | Understand the analysis process, questions, data types and data quality |
| 3–5 | Excel | Clean, analyse and report on spreadsheet data |
| 6–8 | SQL | Retrieve, filter, aggregate and combine relational data |
| 9–11 | Power BI | Transform, model and visualise data in an interactive report |
| 12–14 | Python | Use Python and pandas for data preparation, analysis and visualisation |
| 15 | Capstone | Complete an end-to-end analysis of a realistic problem |
| 16 | Portfolio and presentation | Document, present and publish your work |

**Expected commitment:** 8–12 hours per week.  
**Recommended pass mark:** 70% on assessed work.  
**Duration:** 16 weeks. The programme is sequential; do not skip ahead because a later tool looks more exciting.

## How learning works

Every week follows the same cycle:

1. **Learn:** read the lesson and study the recommended resources.
2. **Follow:** reproduce the worked examples yourself.
3. **Practise:** complete the exercises without copying the solution first.
4. **Submit:** complete the weekly assignment and document your decisions.
5. **Review:** use the rubric, correct mistakes and record what you learned.

A weekly live session can be used for demonstrations, questions, feedback and review. The GitHub materials remain the central source of truth, so learners can study independently.

## Progression rules

- Complete weeks in order.
- Attempt exercises before viewing worked solutions.
- Submit your own work. Explain any help, templates or code you used.
- Aim for at least 70% on each assessed milestone.
- If you score below 70%, review the relevant lesson, correct the work and resubmit.
- Do not treat a dashboard as complete until its figures have been checked against the source data.
- Do not publish private, personal or confidential data.

## What you should finish with

By the end, a committed learner should have:

- A clear understanding of the data analysis workflow.
- Practical experience with Excel, SQL, Power BI and Python.
- At least three documented pieces of work: a spreadsheet analysis, a SQL analysis and an end-to-end capstone.
- A GitHub repository or portfolio that explains the problem, data, process, findings and recommendations.
- Practice presenting findings to a non-technical audience.

Completion of this programme is not a guarantee of employment or professional mastery. Your skill will depend on the quality of your practice, feedback and continued projects.

## Important learning principles

**Questions before tools. Evidence before conclusions. Clarity before decoration.**

A good analyst does not simply produce charts or write formulas. A good analyst understands the question, checks the data, chooses an appropriate method, validates the result and communicates limitations honestly.
